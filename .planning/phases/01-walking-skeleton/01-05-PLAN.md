<objective>
Assemble the four real stages into the synchronous decision pipeline: the identity/trust stage (IDN-02, TRST-01), the floor-respecting graduated-response stage (POL-06), and the `evaluate(action) -> Decision` runner that orders them, accumulates machine-readable reasons (PIPE-02), short-circuits on forged identity (PIPE-03), and writes the audit record before returning (PIPE-01).

Purpose: This is the PDP — the heart of the skeleton. It wires together the identity engine (01-02), the policy floor (01-04), the risk detector (01-03), and the audit writer (01-02). The floor invariant (a `deny` is terminal; risk/trust only restrict) is mandatory here and is exactly what the red-team gate (plan 01-06) proves.
Output: `identity.py`, `graduated.py`, `runner.py` and their unit tests (ordering, short-circuit, floor invariant).
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| action → pipeline | The full untrusted AgentAction enters `evaluate`; stages must run in order and the policy floor must be authoritative over the advisory risk/trust signals. |
| stage outputs → decision | Each stage's reason is recorded into a Decision that becomes immutable audit evidence. |

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-01-15 | Spoofing / Elevation | identity short-circuit | mitigate | Forged/unknown identity → terminal deny WITHOUT running later stages (PIPE-03/IDN-02), still audited. Tested in Task 2 via call-count spies. |
| T-01-16 | Elevation (P0-killer) | graduated stage upgrading a deny | mitigate | `graduated_response` returns deny first if policy denied; property-test sweep proves no (risk,trust) upgrades a deny (POL-05/TRST-02 floor invariant). Tested in Task 1. |

| T-01-18 | Denial of Service | nested event loop | mitigate | No `asyncio.run()` in the runner (grep gate = 0); CPU stages stay sync, only the audit write is awaited (AI-SPEC §4b). |
