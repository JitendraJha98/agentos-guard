  reasons:list[Reason], evidence_ref:UUID|None. model_config = extra="forbid".

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| serialization boundary (`AgentAction`/`Decision` ↔ JSON) | Untrusted/foreign data may be deserialized into the contract types; the boundary must reject unknown shapes. |
| finding → audit log | `RiskFinding.matched` is written into an un-redactable, hash-covered audit record; raw payload must never enter it. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Tampering | `AgentAction`/`Decision` deserialization | mitigate | `model_config = {"extra": "forbid"}` on both — unknown fields rejected at the boundary (ASVS V5 input validation). Tested in Task 2. |
| T-01-02 | Information Disclosure | `RiskFinding.matched` → audit log | mitigate | `_no_raw_payload` `field_validator` rejects URL-like or >64-char strings so the detector cannot leak a secret into the immutable hash-covered log (Pitfall 3 second line of defense). Tested in Task 2. |
| T-01-03 | Tampering | data bounds on scores | mitigate | `risk_score`/`trust_score` bounded `Field(ge=0.0, le=1.0)`; out-of-range raises ValidationError. |
| T-01-SC | Tampering | pip/uv installs (supply chain) | mitigate | All Wave-1 packages are `[VERIFIED: PyPI]` and slopcheck-OK per RESEARCH § Package Legitimacy Audit. The only `[ASSUMED]` package (`opa-wasmtime`) is intentionally NOT installed this wave — gated behind the blocking human-verify checkpoint in plan 01-04. Pin versions in `uv.lock`. |
</threat_model>
